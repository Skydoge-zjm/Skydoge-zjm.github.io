# 博客文章配图

## 从文章里选一个动作

读 `src/content/blog/<slug>.md` 的标题、摘要和与主题最相关的一段正文。找出这篇文章特有的动作或矛盾，再选一个能用轮廓表现它的物件。打开 `src/assets/writing/` 中一两张成图作参照。批量配图时，把相邻几篇放在一起挑构图，让各篇的轮廓容易区分。

《GPT 6 写代码，总有下一件事》画了一摞纸，最上面还有一张即将落下。读者能看出“又加了一件事”。部署博客那篇则用折起、飞出的纸飞机表现发布。借用这种选题方法，每篇重新构图。首页作者介绍旁的抽象线纹是独立作品，文章配图以各自的内容为依据。

## 系列的笔触

- **画布与留白**　在透明的 280 × 108 逻辑画布上构图。现有五张图的主体大致围绕中心 `(140, 54)`，单幅有色部分宽约 80–150、高约 65–75 个单位。把识别主体所需的形状放在中央，细小的光线、纸边等可以往外伸。手机会从两侧裁掉一部分留白。
- **线与面**　用略偏暖的石墨灰画轮廓，主线约 0.8–1.1 个单位，折痕和纹理约 0.45–0.8。用一两块半透明灰面交代前后关系，在有转折的局部加短排线。用少量暖褐标出一道折边、一个日期或一束光。具体 RGBA 色值已放在渲染器的调色板里。
- **细节取舍**　让轮廓在手机缩略尺寸下也能认出来。题目和日期由网页排版，图内留给物件本身。保留透明底，让页面自身的纸色成为底色。

## 绘制与交付

1. 在临时工作目录写一份 Python 画稿，入口为 `draw(pen)`。可以从[纸飞机原稿](assets/paper_plane.py)起笔。[渲染器](scripts/render.py)提供 `line`、`face` 和 `hatch`，坐标和线宽均使用逻辑画布单位。弧线可以用一串采样点连接。
2. 使用装有 Pillow 且支持 WebP 的 Python。下面这条命令可在仓库根目录重画纸飞机；给新文章配图时，换成自己的画稿路径和文章文件名。渲染器以 5 倍分辨率绘制，经 Lanczos 缩小为 **840 × 324**，保存为带透明通道的无损 WebP。

   ```powershell
   $artSkill = '.agents/skills/illustrate-blog-post'
   python -B "$artSkill/scripts/render.py" "$artSkill/assets/paper_plane.py" "$env:TEMP/paper-plane.webp" --proof "$env:TEMP/paper-plane.html"
   ```

3. 打开预览，看浅色纸面、深色纸面以及手机的居中裁切。重点看主轮廓是否完整、叠面能否分开、细线是否糊成一团。手机上看不清时，先收拢主体或减去细节。深色预览沿用站点的 `invert(1) hue-rotate(180deg)`。
4. 将成图放在 **`src/assets/writing/<slug>.webp`**，其中 `<slug>` 是文章 ID（当前对应 Markdown 文件名去掉 `.md`）。网站按文件名自动匹配。缺图时共用 `markdown-showcase.webp`，给其他文章配图时使用各自的文件名。临时画稿和预览页留在工作目录。
5. 文章在首页时，实际点开本地首页核对标题与配图。对于草稿或首页展示范围以外的旧文，用独立预览核对即可。交付时给出成图路径，并用一句话说明所选意象。
